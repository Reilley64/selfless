# selfless

Created in [T3 Code](https://t3.codes).

## Development

Install [mise](https://mise.jdx.dev) and Docker, then run `mise install` and `bun install` in the repository root.

- `mise run services` starts PostgreSQL and grafana/otel-lgtm from `compose.yaml`. Grafana runs at http://localhost:3000.
- `mise run bundle` runs `topcoat asset bundle`, which builds the server and writes the admin app's assets (its stylesheet, its time script and htmx, downloaded and checked against its hash) to an `assets` directory beside the binary. The server loads that bundle at startup, or the one in `ASSETS__DIR`, and exits if it is missing. `mise run test` and `mise run dev` run it first. Run it again after changing the admin stylesheet or scripts.
- `cargo run` starts the server. It reads `DATABASE__URL` (set in `mise.toml`) and `HTTP__PORT` (default 8080). It serves the web export from `WEB__DIR` (default `presentation/web/dist`) at `/`. It sends traces, metrics and logs over OTLP gRPC to `localhost:4317`. The standard `OTEL_*` variables change this, and `mise.toml` sets `OTEL_SERVICE_NAME`.
- The server sends email over SMTP. It reads `SMTP__HOST`, `SMTP__PORT`, `SMTP__USERNAME`, `SMTP__PASSWORD` and `SMTP__FROM` (a mailbox such as `selfless <selfless@example.com>`), and it exits at startup naming any that is missing. Port 465 uses implicit TLS. Any other port uses STARTTLS, and a send fails if the SMTP server doesn't offer it. `mise.toml` sets placeholder values so the server starts, but sends fail until `mise.local.toml` points them at a real SMTP server.
- The admin app is at `/admin`. When the database has no admin, the server creates one from `ADMIN__USERNAME` and `ADMIN__PASSWORD` at startup, and exits with an error if either is missing. Once an admin exists, it ignores them. `mise.toml` sets both to `admin` for development. An admin session ends after 12 hours without use.
- Radarr sends its webhooks to `/webhooks/radarr/v1` by `POST` or `PUT`, with HTTP Basic credentials. The server checks only the password, against `RADARR__WEBHOOK_PASSWORD`, and exits at startup if it is missing. `mise.toml` sets it to `radarr` for development. A wrong or missing password gets 401 and counts as a rejected webhook in the sync status. With the right password, the server stores the delivery as an inbox row and returns 200, and the inbox worker processes it straight away. The webhook endpoints are not in `openapi.yaml`. The worker re-syncs the movie named by a `Download`, `Rename`, `MovieAdded`, `MovieDelete` or `MovieFileDelete` delivery from Radarr's API at `RADARR__URL`, sending `RADARR__API_KEY` as `X-Api-Key`. The server exits at startup if either is missing.
- Sonarr sends its webhooks to `/webhooks/sonarr/v1` in the same way, checked against `SONARR__WEBHOOK_PASSWORD`. The inbox worker re-syncs the show a library event names from the Sonarr API at `SONARR__URL` with `SONARR__API_KEY`. The server exits at startup if any of the three is missing. `mise.toml` sets them for a Sonarr on `localhost:8989`. An episode is in the library only when Sonarr reports a file for it and the file exists at the same path on the server's disk.
- A delivery that fails to process is retried after 1, 5, 15 and 30 minutes. After the fifth failed attempt it shows as failed in the sync status until an admin retries it or a reconcile syncs the same movie or show. Processed, ignored and resolved deliveries are deleted 30 days after they were received.
- The server reconciles the library with the full Radarr and Sonarr listings at startup and every `LIBRARY_SYNC__RECONCILE_INTERVAL`, a duration such as `1h` (the default). A reconcile removes nothing unless every call to that app succeeded. If it would remove more than half of an app's items, it holds the removal until an admin confirms it.
- A movie's metadata comes from its Kodi NFO, which has the media file's name with `.nfo`. Without an NFO, or with one the server can't read, the title, year, genres and overview come from Radarr, and the sync status lists an unreadable NFO as a problem with its path. `poster.jpg`, `fanart.jpg` and `clearlogo.png` in the movie folder are the movie's artwork. A reconcile picks up NFO and image changes from their modification times.
- A show's metadata comes from `tvshow.nfo` in the show folder, and each episode's from the NFO with the episode file's name. A file holding several episodes has one `<episodedetails>` per episode, matched by its Sonarr `uniqueid`, or by season and episode number when it has none. Without an NFO, or with one the server can't read, the title, year, genres and overview come from Sonarr, and the sync status lists an unreadable NFO. A new show uses Sonarr's fields until a reconcile finds its `tvshow.nfo`. `poster.jpg`, `fanart.jpg` and `clearlogo.png` in the show folder are the show's artwork, `seasonNN-poster.jpg` and `season-specials-poster.jpg` the season posters, and the episode file's name with `-thumb.jpg` the episode thumb.
- The server relays app telemetry. It takes OTLP/HTTP protobuf at `/api/telemetry/traces/v1`, `/api/telemetry/metrics/v1` and `/api/telemetry/logs/v1` and forwards it over gRPC to the same OTLP endpoint its own exporters use. It needs a signed-in user's session token, like every other `/api` endpoint.
- The web app reports as `selfless-web` and sends its traces, metrics and logs to the relay. Each API call gets a client span and a `traceparent` header, so a trace in Grafana starts in the web app and continues on the server.
- `mise run dev` starts PostgreSQL, the server and the web app's dev server on port 8081. The dev server sends `/actuator` and `/api` requests to the server.
- The TV app in `presentation/tv` reports as `selfless-tv`. On first launch it asks for the server address and checks it with `/actuator/info/v1`, for example `localhost:8080` on the tvOS Simulator and `10.0.2.2:8080` on the Android emulator. It keeps the address and its user picker list in expo-secure-store. `react-native` is the tvOS fork in the catalog and in the root `overrides`. When Expo moves to a new SDK, change `expo`, the `react-native` catalog entry and the override together. Its native folders are not committed. `bun run prebuild` in `presentation/tv` writes them for TV with `EXPO_TV=1`. Then `bun run ios` builds a development build for the tvOS Simulator, and `bun run android` builds one for an Android TV emulator. `./gradlew assembleRelease` in `presentation/tv/android` writes a TV-only APK.
- `bun run generate` writes the API client from `openapi.yaml` and the TypeScript telemetry constants from `telemetry/registry`. It also builds the theme from the design tokens in `tokens`. Style Dictionary writes a Tailwind `@theme` file, a native-only font block and the admin app's topcoat-ui variables (`tokens/admin.tokens.json`) to `presentation/ui/theme`. Tailwind then writes the admin stylesheet to `presentation/admin/dist`. Run it again after changing any of these. `bun run typecheck`, `bun run lint` and `bun run test` check the apps, and `bun run export` writes the web export to `presentation/web/dist`.
- The server build reads the branch, commit and commit time for `/actuator/info/v1` from git. `GIT_BRANCH`, `GIT_COMMIT` and `GIT_COMMIT_TIME` override them, for builds outside a git checkout.
- A cargo build runs Weaver to generate Rust constants from `telemetry/registry`. `mise run lint:telemetry` checks the registry.
- `mise run test` runs the server tests against that PostgreSQL. Each test creates its own database.
- `mise run check` checks formatting, Clippy lints and crate direction.
- `mise run lint:openapi` lints `openapi.yaml`.
- `mise run build:image` builds the container image for linux/amd64 as `selfless:local`, with the git values and the version as build arguments. `mise run test:image` also starts it beside PostgreSQL and waits for readiness to return `UP`. CI runs the same check on pull requests. On an arm64 Mac, Docker emulates amd64, and the first build takes about 12 minutes.
- The image runs as user 10001. It serves the web export from `/app/web` and the admin assets from `/app/assets`, and has jellyfin-ffmpeg in `/usr/lib/jellyfin-ffmpeg`. Its license is in `/usr/share/doc/jellyfin-ffmpeg8/copyright`, and `SOURCE` beside it links to the source. The image has no `HEALTHCHECK`. Use the actuator endpoints instead. On SIGTERM the server reports `OUT_OF_SERVICE` for 5 seconds, then gives in-flight requests up to 30 seconds, so the orchestrator's kill timeout must be longer than 35 seconds.
- `cargo run --bin toasty -- migration generate` writes a migration for changed models to `infrastructure/persistence/toasty`. The server applies pending migrations when it starts.

## Releases

Every push to `main` runs "Build, release and publish: Application". It builds the image, smoke tests it and pushes `ghcr.io/reilley64/selfless:<sha8>` and `:latest`. release-please keeps a release pull request open. It reads the conventional commit titles on `main` and sets one version for every crate in `Cargo.toml` and `Cargo.lock` and for `expo.version` in `presentation/web/app.json` and `presentation/tv/app.json`. Merging that pull request creates the `vX.Y.Z` release, and the workflow adds the `vX.Y.Z` and `release` tags to the image it built for that commit. Each crate sets `version` itself, because release-please cannot update `version.workspace = true`. A new crate starts at the current version, and `mise run lint:versions` checks this.
